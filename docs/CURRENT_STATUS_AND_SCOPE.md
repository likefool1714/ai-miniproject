# 현재 완료 범위·화면 확인·추가 기능 구분

2026-10-22 기준. 완료 여부는 코드·이전 검증 원문과 현재 앱의 새 실행을 대조했다.
이 문서의 “완료”는 로컬 샘플 환경의 등록 기능 구현·검증을 뜻한다. 과제 전체 제출 완료를 뜻하지 않는다.

## 현재 상태

추가 감사에서 발견한 4종류를 수정하고 77개 회귀 검사와 수정본 제공 API 검사를 통과했다. [새 검증·실제 화면](../results/bugfix-2026-10-21/README.md). 기존 아래 5/5·15/15 기록은 앞선 실행으로 구분한다. 현재 라이트 Vue 사진·실제 기동 로그·보고서를 담은 본문 9장+부록 3장 최종 발표자료로 갱신했다.

- 처음 등록한 개선 5항목·추가 5항목은 구현되어 있다. 수치의 의미·원인 점검 방향 설명도 보완했다.
- 현재 앱에서 새 대화로 진단→부분 회복→부분 회복(정상 1회)→복구 확인→재발을 실행해 5/5 일치했다.
- 같은 대화의 이력 5건, 이력/보고서 열람 시 관측 추가 없음, Markdown 다운로드를 확인했다.
- 이 새 실행의 최초 진단은 실제 Ollama 검증을 통과했다. 데이터는 합성 시나리오다.
- 제공 API 실제 일반 진단 POST 3건·SSE 1건과 후속 복구 5단계·이력·보고서 확인을 마쳤다. [실제 결과](../results/api-2026-10-21/README.md).
- 사용자가 승인한 Canva 본문 9장+부록 3장 PPT·PDF와 대응하는 5분 대본을 작성했다. LangSmith 실제 추적과 실제 발표·제출은 별도다.
- 이번 API 확인에서 제품 코드를 바꾸거나 새 기능을 추가하지 않았다.

## 처음 등록했던 추가 기능 — 이미 구현

| 추가 기능 | 확인 방법 |
|---|---|
| 조사 이력 저장·조회 | “조사 이력” 버튼. 저장 시각·상태·CPU·메모리·알림·당시 판정 표시 |
| 상태 변화 비교 | 같은 서비스 재점검 답변에서 변화량과 알림 발생·해소 확인 |
| 복구 재점검 | “복구 재점검” 버튼. 새 관측 조회 후 복구 조건 확인 |
| 장애 재발 감지 | 복구 확인 뒤 다시 이상을 조회하면 “장애 재발” 표시 |
| 조사 결과 내보내기 | “Markdown 보고서” 버튼. 근거·변화·판정·이력·정책·한계 포함 |

등록 내용의 “진단 방식 개선”과 “상태 변화 비교 추가” 등은 같은 구현을 공유한다. 10개의 독립 알고리즘을 만들었다고 설명하지 않는다.

## 중복을 줄인 소개 문안

원래 등록 범위를 바꾸는 내용이 아니라, 같은 기능을 두 번 세지 않도록 소개 표현을 정리한 것이다.

**[개선 사항 — 기존 응답 동작 보완]**

- 답변 품질 개선: 관측 수치에 상태 해석·근거·점검 방향·조건부 조치 설명을 함께 제공.
- 대화 대상 처리 개선: 서비스 누락 시 확인 질문, 후속 요청에서 이전 조사 대상 유지.
- 검증·예외 처리 개선: 근거 없는 제안 반려, 수치 조건 검사, 오래된 자료·중복 관측·조회 실패·생성 지연 처리.

**[기능 추가 — 기존에 없던 사용 기능, 현재 구현 완료]**

- 서비스별 조사 이력 저장·조회.
- 이전 조사 대비 수치·알림 변화 비교.
- 신규 관측을 통한 복구 재점검과 연속 정상 관측 판정.
- 복구 이후 장애 재발 감지.
- 조사 결과 Markdown 보고서 내보내기.

## 앞으로 새로 추가할 수 있는 기능 — 제안, 미구현

새로 확정해 구현 중인 기능은 현재 없다. 위 추가 기능 5개를 앞으로 구현할 예정이라고 설명하면 부정확하다.
초기 후보로 **운영자 조치 기록·인수인계 메모**를 검토했다. 이후 전체 검토에서는 새로운 조사 능력을 보여 주는 **서비스 의존관계 기반 연관 조사·영향 안내**를 우선 추천했다. 두 안 모두 미구현·미확정이며 [전체 후보 검토](FEATURE_REVIEW.md)에 차이와 범위를 정리했다.

- 운영자가 조치명·시각·결과·메모를 입력하고 해당 서비스의 관측 기록과 연결.
- 다음 담당자가 어떤 대응을 시도했는지 확인.
- 보고서에서 자동 모니터링 관측과 “사용자 입력 조치 기록”을 구분해 표시.

기존 조사 이력은 CPU·메모리 등 관측을 자동 저장한다. 이 후보는 사람이 보고한 대응 활동을 별도로 기록하는 기능이다.
실제 조치 수행 여부를 에이전트가 검증하는 기능이나 자동 조치 실행 기능은 아니다. 사용자 기록이라는 출처를 명시해야 한다.
이 후보는 아직 구현하지 않았고 새 개발 범위로 확정하지 않았다.

등록 기능의 로컬·API 확인과 최종 발표 자료 작성을 마쳤다. 다음은 오늘 13시 발표 전 코드 설명·발표 연습과 제출 링크 점검이다. LangSmith 실제 추적은 미검증으로 남긴다.
