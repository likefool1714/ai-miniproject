# 개발 계획

과제 1번 - 기존 운영 장애 대응 에이전트의 기능 개선/추가.

## 목표와 선택 이유

제공 서버·웹·LangGraph·MCP 구조를 활용해 조사 대상의 임의 대체/누락과 근거 없는 답변을 개선한다. 원본 반복 검증에서 직접 확인한 문제를 우선하고, 직접 변경한 코드 흐름과 전후 수치를 설명할 수 있는 범위로 제한한다.

당초 대상 확인+런북 RAG를 검토했으나, 원본 18회 실행 결과를 반영해 핵심 B를 근거 기반 답변 검증으로 조정했다. RAG는 후속 확장 후보로 둔다.

## 핵심 A: 조사 대상 검증과 확인 상태

- 등록 서비스 목록을 공통 모듈로 관리한다.
- 대상 누락/미등록 시 확인 질문을 반환하고 모니터링을 실행하지 않는다.
- 명시 대상과 계획 대상의 집합을 대조해 빠진 대상을 보충하고 임의 추가를 통제한다.
- 확인 대기 상태에 원래 요청/증상/대상을 보존한다. 확인 응답과 일반 대화를 구분한다.
- 같은 thread의 후속 대상 참조와 취소/불명확 응답을 처리한다.
- POST와 SSE의 동작을 일치시킨다.

## 핵심 B: 근거와 답변 검증

- 확인된 사실/가능한 원인/권장 조치/추가 확인 사항을 구분한다.
- 자동 검증 가능한 서비스명과 수치를 수집 결과에 대조한다.
- 실제 조회한 출처를 연결하고 미조회 자료의 분석 완료 표현을 검사한다.
- 재작성 한도를 넘으면 합격으로 바꾸는 대신 검증 실패/부분 답변을 표시한다.
- 생성량과 전체 요청 시간 제한, 취소/오류 이벤트를 공통 보완한다.

## 범위와 중단 기준

실제 운영 조치, 추가 멀티에이전트 구조, 승인·재개, 로그인/배포, 데이터 규모 확대는 제외한다. 핵심 기능의 오류가 남아 있으면 RAG/화면 꾸미기보다 검증과 문서 정리를 우선한다. 제출하지 못한 기능은 완료로 기재하지 않는다.

## 완료 정의

두 기능의 API/웹 동작, 누락/미등록/복수/후속/오류 사례, 고정 조건의 Before/After 원시 기록과 집계, 제공 API 확인, 한계·실패 사례, 실제 수치를 넣은 PPT/보고서를 갖춘다. 상세 대응은 [요구사항 교차 확인](REQUIREMENTS_CROSSCHECK.md)과 [평가 설계](EVALUATION.md)를 따른다.
