# 개발 계획

과제 1번. 최종 등록 범위는 상태 변화 비교·복구 확인·이력·재발·보고서다.
초기 대상 확인/일반 답변 검증 중심 검토에서 사용자가 최종 등록한 범위로 변경했다.
RAG·운영 조치·모든 자연어 사실 검증은 이번 핵심 범위가 아니다.

## 순서

1. 관측 스키마·정책·순수 판정
2. SQLite 이력·대화 대상·최근 실패 저장
3. MCP 출처·관측 ID·대화별 고정 시나리오
4. LangGraph 재점검/판정/이력/보고서 노드
5. POST/SSE·웹 버튼·다운로드 연결
6. 단위·실제 MCP/API·브라우저 확인
7. 고정 조건 원본/개선 비교·README 반영
8. 제공 API/LangSmith·최종 PPT/보고서

10/20 17:00 전 공개 README와 당일 구현·검증 결과를 게시한다.
10/21 오늘 제공 API 실제 확인과 최종 PPT·대본·필요한 PDF까지 마무리하고 재현·제출 링크를 점검한다.
10/22 09:00~13:00은 구현 이해·코드 설명·발표 연습에 사용한다. 사용자가 안내한 발표 시작은 10/22 13:00이다.
과제의 제출 마감과 발표 시각은 별도로 확인한다. 제공 API는 실제 기능 검사 완료, LangSmith 실제 추적은 미검증이다. 화면은 기능 연결을 우선한다.

현재 1~7과 일반 진단의 근거 검증 보완까지 구현했다. 기존 8장 PPT는 초안으로 보존한다.
사용자 요청에 따라 로컬·제공 API 확인 후 발표 자료를 작성한 뒤 사용자 요청으로 Canva 표지 포함 9장으로 재구성하고 PPT·PDF·5분 대본을 정리했다.
LangSmith 실제 추적과 실제 발표·최종 제출은 완료로 표시하지 않는다.
