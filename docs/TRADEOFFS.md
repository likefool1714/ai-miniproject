# 한계·트레이드오프

| 선택 | 이점 | 한계 |
|---|---|---|
| 여러 신호 함께 판정 | CPU만 보고 복구 오판 억제 | 오래된 알림 하나로 보류 가능 |
| 5초 간격 정상 2회 | 단발 정상·중복 조회 방지 | 확인 지연, 관측 사이 정상 보장 못함 |
| 300초 유효시간 | 오래된 자료 사용 방지 | 느린·드문 조사에서 보류 증가 |
| 코드 기반 복구 | 재현 가능, LLM 호출 감소 | 복잡한 원인·사용자 결제 성공 미확인 |
| SQLite | 재시작 후 유지 | 저장 비용, 보관·삭제·권한 정책 미구현 |
| 고정 시나리오 | 재현 가능 | 합성 편향, 실제 장애 대표 못함 |
| 구조화 제안·근거 ID 검증 | 미수집 사실·임의 수치·타 서비스 근거 혼용 차단 | 자유 설명과 원인 후보 범위 제한 |
| 검증 뒤 최종 출력 | 반려된 초안이 사용자에게 먼저 노출되지 않음 | 일반 진단의 첫 답변 대기 증가 |
| 재작성 한 번 후 보류 | 무한 반복·실패 강제 통과 방지 | 사용할 만한 제안도 보수적으로 보류 가능 |
| 소형 모델 생성 제한·실패 시 코드 계획 | 긴 생성과 실패 전파 억제 | 복잡한 계획은 단순 대상 조회로 축소 |

기준은 교육용 정책이며 실제 SLO가 아니다.
명령 해석은 제한된 표현을 지원한다. 자동 조치·주기 감시·운영 배포는 제외한다.
근거 검증은 v2 일반 진단의 제한된 스키마에 적용한다. 원인 확정·런북 자체 정확성·일반 대화의 모든 사실을 검증하지 않는다.
제공 런북의 CPU·메모리 수치 조건만 해석하며 지속 시간, 배포·로그·디스크 상세 조건은 추가 자료가 필요하다.
원본에 없던 기능의 지원 여부와 자연어 의미 정확도는 구분해 평가한다.
