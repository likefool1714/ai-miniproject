## 본문 6장 - 목표 5분

| 장 | 주제 | 목표 시간 |
|---|---|---:|
| 1 | 문제: 정상 1회에서 조기 복구 확정 | 40초 |
| 2 | 구조·직접 기여: 대상 확인·저장·판정·근거 검증 | 40초 |
| 3 | 개선: 이전 상태·연속 정상 관측·복구·재발 | 70초 |
| 4 | 근거·점검 방향 설명과 추가 사용 기능 | 40초 |
| 5 | 같은 입력 Before/After와 실제 제공 API 결과 | 70초 |
| 6 | 한계·트레이드오프·후속 개선 | 40초 |

총 300초는 계획이다. 실제 발화 시간은 내일 2회 연습해 조정한다.
원본/개선 비교는 로컬 Ollama·고정 MCP 입력이며, 실제 제공 API 검사는 별도의 기능 호환 확인이다.

## 참고 2장 - 질문이 있을 때만

7. 코드에서 설명할 다섯 곳: 대상 복원·관측 조회·저장·정책 판정·근거 검증/설명.
8. 실제 API 모드에서 정상 1회를 복구로 확정하지 않는 앱 화면.

PPT에는 각 장의 발표자 노트에 대본과 근거를 포함했다.
구조·레이아웃 검사 및 전체 슬라이드 렌더 확인을 수행했다. 실제 PowerPoint 앱에서 열어 확인한 것으로 설명하지 않는다.
LangSmith 실제 추적은 미검증이며 완료 기술로 소개하지 않는다.
