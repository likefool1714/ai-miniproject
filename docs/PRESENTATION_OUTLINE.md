# 발표 구성안

실측 결과·실행 화면·코드 역할을 담은 8장 PPT를 작성했다.
파일: output/presentation/AI-Mini-Project_G028_최민석.pptx
발표자 노트에 출처와 설명을 포함했다. 실제 PowerPoint 앱에서 열어 본 것으로 기재하지 않는다.

1. 문제: 현재 수치만으로 이전 변화·단발 정상·재발을 확인하기 어렵다.
2. 개선: 이력과 여러 신호·연속 관측으로 상태 변화·복구 확인.
3. 구조: 기존 Supervisor/MCP 재사용, 새 요청 분기·노드·저장소.
4. 데모: 장애 → 부분 회복 → 정상 1회 보류 → 복구 → 재발.
5. 코드: MCP → SQLite record → 순수 assess → 응답/보고서.
6. 실측: 동일 질문·관측, 원문·판정·시간. I/O 통제와 LLM 생략을 설명.
7. 한계: 합성 데이터, 정책 의존, 확인 지연, 사용자 트랜잭션 미확인.
8. 후속: 실제 메트릭·서비스별 SLO·보관 정책·제공 API/추적.

질문 대비:
- 정상 2회는 왜? 단발 정상 오판을 줄이는 교육용 정책이다.
- AI는 어디서? 기존 자연어 진단의 분류·계획·조언. 복구 확정은 코드가 담당한다.
- CPU 55%인데 왜 보류? 메모리·상태·알림·정상 횟수도 함께 확인한다.
