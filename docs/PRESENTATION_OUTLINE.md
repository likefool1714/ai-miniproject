# 발표 7장 구성안

현재는 발표 구조와 설명 초안입니다. 최종 PPT 파일은 구현/측정 후 실제 화면과 수치를 넣어 작성합니다.

| 장 | 제목 | 넣을 내용 | 설명 핵심 |
|---|---|---|---|
| 1 | 문제와 목표 | 제공 프로젝트, 3일 범위, 개선 두 가지 | “불명확한 대상과 단순한 매뉴얼 선택을 개선했습니다.” 구현 전에는 계획형 표현 사용 |
| 2 | 기존 동작의 약점 | 실제 재현 입력/기준 SHA/Before 화면 | 대상 누락 기본값, 영어 키워드 우선순위의 문제 |
| 3 | 개선 A: 대상 서비스 확인 | 검사 → 확인 질문 → 후속 입력 → 조사 흐름 및 핵심 코드 | 모델 판단과 코드 검증을 구분 |
| 4 | 개선 B: 런북 RAG | 문서 → 임베딩 → 검색 → MCP 본문 → 근거 답변 흐름 | 검색만 하는 것이 아니라 본문을 생성에 전달 |
| 5 | Before/After 실측 | 동일 평가셋의 분자/분모, 지연, 실패 케이스 | 측정 전 수치 미삽입, fake/Ollama/API 구분 |
| 6 | 한계와 트레이드오프 | 추가 확인 턴, 임베딩 지연, 작은 데이터, 복합 장애 | 더 좋아진 점과 새로 생긴 비용을 함께 설명 |
| 7 | 기여와 다음 개선 | 제공/직접 구현 구분, 저장소/재현법, 다음 개선 1-2개 | 새 구조 추가보다 설명 가능한 개선과 검증을 완성 |

발표 목표 약 5분. 코드를 전부 읽지 않고 변경 지점 2곳과 실제 입력 흐름으로 설명합니다. 평가 결과가 기대와 다르면 실패 원인과 후속 계획을 그대로 넣습니다.
