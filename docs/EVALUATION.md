# Before/After 평가 설계

현재 평가 실행기와 개선 기능은 미구현이며, 아래 수치는 아직 측정하지 않았습니다.

## 기준 고정

- Before: `d1043ff`의 **v2**. After: 개선 완료 커밋의 v2.
- 같은 평가 ID/입력/대화 이력/모니터링 스냅샷/런북 본문을 사용합니다.
- fake 분기 검사, Ollama 실모델 결과, 원격 API 결과를 구분합니다. fake 성공을 실모델 성능으로 쓰지 않습니다.
- 동일 백엔드 안에서 Before/After를 비교합니다. 로컬 Before와 API After를 기능 효과로 비교하지 않습니다.
- API/Ollama의 사용 모델 이름, 설정, 임베딩 모델, 버전, 실행 환경을 저장합니다.

## 핵심 지표

| 지표 | 계산 | 주의점 |
|---|---|---|
| 대상 처리 정확도 | 기대 대상 집합 또는 확인 필요 여부가 일치한 건수 / 전체 | 명시 대상·대상 누락·미등록 각각 집계 |
| 잘못된 조회 수 | 승인/명시되지 않은 서비스의 Tool 호출 수 | 확인 질문 전에 호출했는지 검사 |
| 런북 Top-1 정확도 | 기대 incident_type을 1위로 반환한 건수 / 검색 문항 | 순수 검색 결과 기준, 답변 문장과 분리 |
| 검색 실패 처리 | 인덱스/임베딩 실패 시 정의된 오류/보류 응답 여부 | 조용한 기본값 대체 금지 |
| 지연시간 | 검색 구간 및 요청 전체의 중앙값, 범위 | 인덱스 생성/첫 모델 로드를 별도 기록 |
| 확인 대화 성공 | 확인 후 원래 증상을 유지하고 맞는 대상을 조회한 대화 / 확인 대화 | 해결까지 걸린 턴 수도 기록 |

## 평가셋 초안

`eval/cases.jsonl`의 20개 케이스를 우선 검토합니다. 이는 **평가 설계 입력**이며, Before 코드에서 실제 재현된 실패라고 단정하지 않습니다.

- 대상 처리 8개: 명시 단일, 명시 복수, 대상 없음, 미등록, 잡담, 확인 후속, 확인 취소, 불명확 재응답.
- 런북 검색 12개: 6개 유형별 2개, 한국어 바꿔 말하기 포함.
- 검색 문항의 `query`와 `alerts`를 Before/After에 동일하게 제공합니다. 기존 분류는 alerts를 주로 사용한다는 구조 차이를 보고합니다.
- 검색 모델/임계값 선택에는 별도 개발 질문을 사용합니다. 최종 평가 질문으로 정답을 맞추는 규칙을 추가하지 않습니다.
- 현재 20개는 작은 편의 표본이므로, 일반적인 정확도 보장을 주장하지 않습니다.

## 공정한 측정을 위한 조치

제공 MCP Tool은 난수 지터와 현재 시각을 생성합니다. 같은 메시지라도 실제 입력 데이터가 달라질 수 있으므로 평가 시 고정 스냅샷/테스트 의존성을 주입하고, 웹 데모의 난수 모드 결과와 구분합니다.

research_node에는 교육 목적의 태스크당 `0.35초` 지연이 있습니다. 같은 조건으로 유지하거나 양쪽 모두 제거하고 기록합니다. 이를 검색 개선의 속도 효과라고 설명하지 않습니다.

모델 준비/웜업 → 각 조건 반복 측정(가능하면 3회) → 원시 결과 보존 → 중앙값 집계 순서로 진행합니다. 시간이 부족하면 반복 횟수를 줄였다고 명시하며, 실행하지 않은 숫자는 채우지 않습니다.

## 비용 표시

제공 코드의 `cost_usd`는 모델별 단일 가상 단가로 계산한 추정치입니다. OpenAI 래퍼도 실제 청구액과 다르므로 청구 비용 절감이라고 주장하지 않습니다. Ollama는 API 사용료와 로컬 자원 사용을 구분합니다. 이번 기본 비교는 정확도/지연/불필요 조회를 우선합니다.

## 결과 파일 계획

`results/raw-<backend>.jsonl`: case_id, mode, input, expected, actual, passed, latency_ms, tool_calls, source, retrieval_score, error, model, timestamp, commit.

`results/summary-<backend>.md`: 각 지표의 분자/분모, 중앙값, 실패 ID, 반복 수, 환경과 한계.

## 시연/캡처

같은 단일 대상 입력, 대상 누락 → 확인 후속 입력, 영어 키워드 없는 한국어 증상, 검색 실패를 시연합니다. 각 캡처에는 백엔드/모델/모드/입력을 식별 가능하게 남깁니다. 제공 doc의 이미지들은 예제 자료이며 이번 Before/After의 증거로 재사용하지 않습니다.
