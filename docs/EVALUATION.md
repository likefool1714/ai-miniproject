# 개선 전후 평가 설계

원본 감사 실행기와 18회 기록은 [검증 보고서](BASELINE_VALIDATION.md)에 보존했다. 개선 기능과 정식 Before/After 비교는 아직 미완료이다.

## 조건 고정

- Before: `d1043ff`의 v2 제품 코드. After: 개선 완료 커밋의 v2.
- 기존 18회는 난수 모니터링을 쓴 탐색/재현 기록이다. 정식 비교에서는 양쪽에 동일한 입력/이력/모니터링 스냅샷/런북을 주입해 기준도 다시 측정한다.
- 모델 이름/버전/설정, 소스 SHA, 환경, 입력과 원시 출력을 보존한다.
- fake 분기 검사, Ollama 실모델 결과, 제공 API 확인을 구분한다. 서로 다른 백엔드를 전후 효과로 비교하지 않는다.
- 개발 질문과 최종 평가 질문을 구분하고 평가 입력을 동결한다.

## 핵심 평가

| 항목 | 검사 방법 | 완료 목표 |
|---|---|---|
| 누락/미등록 대상 | 확인 전 Tool 호출과 확인 질문 검사 | 임의의 서비스 조회 0건 |
| 명시 단일/복수 대상 | 기대 대상 집합과 실제 Tool 대상 집합 비교 | 명시 대상의 조사 누락 없음 |
| 확인/후속 문맥 | 같은 thread에서 원래 증상과 대상 유지 여부 | 확인 후 올바른 조사, 모호한 참조는 재확인 |
| 수치/출처 검증 | 수집값과 다른 수치, 미수집 출처 문장을 통제 입력으로 주입 | 정의한 검증 범위에서 탐지, 실패 상태 노출 |
| 실제 모델 답변 | 최종 프롬프트와 답변을 수동 대조 | 관측/추정/권고 구분과 오류 건수 기록 |
| 생성/시간 제한 | 장기 생성·도구 오류를 통제해 주입 | 제한된 시간·시도 안에 중단/오류 안내 |
| 지연/재작성 | 요청 전체 시간과 재시도/재작성 횟수 수집 | 중앙값과 추가 지연 보고, 감소를 가정하지 않음 |

기존 `eval/cases.jsonl`에는 최초 RAG 검토 시 작성한 검색 평가 초안도 포함된다. 대상/대화 케이스는 참고하고, 핵심 B 구현 시 수치/출처/중단 케이스를 별도로 추가한다. 검색 초안을 실행한 실제 RAG 평가 결과로 주장하지 않는다.

## 실측 방법

웜업 후 가능한 경우 같은 조건에서 각 3회 실행하고 분자/분모·중앙값·범위·실패 ID를 기록한다. 인덱스/모델 준비 시간은 요청 시간과 구분한다. 단위 검사의 반복과 실제 모델의 반복을 구분한다.

원본 research_node의 태스크당 0.35초 교육용 지연은 양쪽에 동일하게 유지하거나 동일하게 제거하고 설정을 기록한다. 제공 `cost_usd`는 가상 단가 기반이므로 실제 청구액이라고 표시하지 않는다.

| 지표 | Before | After |
|---|---|---|
| 대상 누락 시 임의 조회 | 탐색 기록 3/3, 고정 데이터 기준 재측정 예정 | 미측정 |
| 미등록 요청의 다른 서비스 조회 | 탐색 기록 3/3, 고정 데이터 기준 재측정 예정 | 미측정 |
| 복수 대상 누락 | 탐색 기록 3/3, 고정 데이터 기준 재측정 예정 | 미측정 |
| 미수집 로그 분석 완료 표현 | 결제 요청 3/3 수동 대조, 재측정 예정 | 미측정 |
| 시나리오별 지연/재작성 | 원본 기록 보존, 고정 조건 재측정 예정 | 미측정 |

결과 파일에는 case_id, 입력, 기대값, 실제 대상/답변/근거, 통과 여부, 지연, 모델/설정, 커밋, 오류를 남긴다. 실제 실행하지 않은 수치는 채우지 않는다.

## 범위와 한계

정의한 코드 검증이 자연어 전체의 사실성을 보장하지 않는다. LLM-as-judge를 추가하지 않으며, 수치·대상 등 결정 가능한 검사와 수동 근거 대조를 구분한다. 소규모 평가셋 결과를 일반적인 운영 정확도로 확대하지 않는다.
