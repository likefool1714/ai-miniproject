- 검사: 6개 테스트 파일, 91개 단위·통합·회귀 검사. 실제 모델 API 91건이 아니다.

## 왜 새 RAG·자율 협업을 추가하지 않았나

LangGraph는 이미 적용했다. 기존 조사·분석·작성 역할 분담도 재사용했다. 'Multi-Agent를 전혀 쓰지 않았다' 또는 'LangGraph를 도입하지 않았다'고 설명하지 않는다. 독립 에이전트 토론·새 협업 프로토콜은 추가하지 않았다.
런북은 장애 유형별 MCP Resource 조회다. 외부 문서를 근거로 답하지만 새 임베딩·벡터DB·유사도 검색 RAG 파이프라인은 없다. 제공 문서 범위와 이번 상태 비교·복구 목표에 맞춰 기존 조회를 유지했다.
추가 자율 협업은 호출·문맥 전달·결과 합의 검증 범위를 늘리므로 이번 마감에서는 재현 가능한 판정과 근거 검사에 집중했다. RAG·다중 에이전트 비교 실험은 하지 않았으므로 성능·비용이 반드시 더 나쁘거나 좋다고 주장하지 않는다.
RAG는 관련 문서 검색 실패, 협업은 여러 모델의 같은 오류 수용 가능성이 남는다. 근거 검사 없이 도입만으로 할루시네이션이 사라지지는 않는다. 이는 본 프로젝트의 성능 비교 결과가 아닌 설계상 주의점이다.

## LLM이 실제로 하는 일

일반 진단에서 분류·계획·선택적 패턴 분석·근거 ID와 진단 항목·런북 절차 선택에 사용한다. 최종 표시 문장과 수치는 코드가 선택 결과·검증된 관측·런북에 연결해 구성한다. 복구 재점검·이력·보고서는 LLM을 호출하지 않는다.
진단 의도 요청에 '복구'가 들어가도 방법·원인·분석을 묻는 경우 일반 진단으로 보낸다. '복구됐어?'는 재점검이다. '보고서 형식으로 정리'는 진단 경로이고 '보고서 내보내기'는 저장된 자료의 파일 생성이다.
로그 요청을 진단으로 보낸다고 실제 로그 도구가 생기지는 않는다. 출력의 확인 범위에서 로그 미수집과 조치 미실행을 명시한다.
